# Steering: Project Structure

```

    └── steering/

        └── structure.md     # this file
```

## Module Boundaries Inside `expense_parser.py`

The single script is divided into five logical sections, in this order:

### 1. `PDFExtractor`
Responsibility: open a PDF with `pdfplumber` and return a list of raw transaction dicts.

Each transaction dict has exactly these keys:
```python
{
    "date": str,          # e.g. "07 Apr 26"
    "description": str,   # payer/payee name from statement
    "type": str,          # FPI | FPO | DD | DEB | BGC
    "money_in": float,    # 0.0 if not present
    "money_out": float,   # 0.0 if not present
    "balance": float,
}
```

### 2. `RulesLoader`
Responsibility: parse `rules.yml` with `pyyaml` and return an ordered list of rule dicts.

Each rule dict has exactly these keys:
```python
{
    "category": str,        # must be one of the 17 valid categories
    "keywords": list[str],  # empty list = match any description
    "types": list[str],     # empty list = match any transaction type
    "default": bool,        # optional, marks catch-all rule
}
```

### 3. `Classifier`
Responsibility: apply rules to transactions and return a mapping of `category → float`.

Rules:
- Iterate rules in order; stop at first match (first-match-wins)
- Keyword match is case-insensitive substring check on `description`
- Type match checks `transaction["type"]` against `rule["types"]`
- `Money In` types (FPI, BGC) → add `money_in` as positive
- `Money Out` types (FPO, DD, DEB) → add `money_out` as positive (stored positive, treated as expenditure in CSV)
- Unmatched transactions are collected separately and written to the unmapped log

### 4. `ReportBuilder`
Responsibility: take the `category → float` mapping and produce the ordered 30-row output list.

- Rows are hardcoded in the sequence defined in `product.md` Section 4
- Missing categories default to `0.0`
- Subtotals and grand totals are computed here, not in `Classifier`
- Returns a list of `(label, value)` tuples in fixed order

### 5. CLI Entry Point (`main`)
Responsibility: wire all components together and handle all I/O.

- Uses `argparse` with arguments matching `product.md` Section 7
- Prints the progress summary to stdout (exact format in `product.md` Section 7)
- Writes the CSV via `csv.writer` to `--output`
- Writes unmapped transactions to `--unmapped-log`
- Raises `SystemExit` with a plain error message (no traceback) for the three error cases in `product.md` Section 8

## Constraints

- **No additional files** — do not split into multiple modules, packages, or helper scripts
- **No additional dependencies** — only `pdfplumber` and `pyyaml` in `requirements.txt`
- **Tests are the only other Python files** — kept in `tests/` and never imported by `expense_parser.py`
- **`rules.yml` at repo root** is the default; it is not the same as `tests/fixtures/sample_rules.yml`
- Spec documents generated by the workflow go under `.claude/specs/{feature_name}/` — never in the project root
